BMP 파일

Bitmap Image File

BMP 파일이란?

BMP(Bitmap) 파일은 각 화소에 색 정보를 차례대로 기록하는 무압축 파일 형식입니다. 확장자는 .bmp이며, 이미지 품질이 우수하지만 파일 크기가 큰 것이 특징입니다.

화소(Pixel)란?

화소(픽셀, Pixel)는 컴퓨터에서 이미지를 구성하는 최소 단위입니다. 디지털 이미지는 수많은 픽셀이 격자 형태로 모여 하나의 그림을 이루게 됩니다.

비트 수에 따른 색 표현

1

각 화소를 0 또는 1로 표현하여 흑백 2색만 나타낼 수 있습니다.

21 = 2색

8비트로 256가지 색상을 표현할 수 있습니다.

28 = 256색
24

24비트

트루 컬러

RGB 각 8비트로 16,777,216색을 표현하는 트루 컬러입니다.

224 = 16,777,216색

장점

  • 압축하지 않아 이미지 품질이 우수합니다.
  • 원본 데이터가 그대로 유지됩니다.

단점

  • 파일 크기가 매우 큽니다.
  • 웹에서 사용하기에 적합하지 않습니다.

이미지 압축이란?

이미지 데이터를 더 적은 용량으로 저장하는 기술입니다. 비손실 압축은 원본 데이터를 완전히 복원할 수 있고, 손실 압축은 일부 데이터를 제거하여 더 높은 압축률을 얻습니다.

파일 형식별 특징

PNG

비손실 압축

  • 반복되는 색 정보를 더 적은 비트로 줄여 표현합니다.
  • 고품질 이미지 처리에 적합합니다.
  • 투명 배경을 지원합니다.
142 KB 예시 파일 크기

GIF

손실 / 비손실 압축

  • 256색으로 제한하여 파일 크기가 작습니다.
  • 256색 이상 이미지는 손실이 발생합니다.
  • 애니메이션을 지원합니다.
59 KB 예시 파일 크기

JPEG

손실 압축

  • 사람 눈으로 인식하지 못하는 색 차이와 세밀한 부분을 제거합니다.
  • 압축률이 매우 높지만 손실이 발생합니다.
  • 사진 등 자연스러운 이미지에 적합합니다.
8 KB 예시 파일 크기

압축 원리 알아보기

PNG 압축 원리

비손실 압축 — Deflate 알고리즘 (LZ77 + 허프만 코딩)

PNG는 데이터를 하나도 버리지 않으면서 파일 크기를 줄입니다. 크게 두 단계를 거칩니다.

1 필터링 — 이웃 픽셀과의 차이만 기록

하늘 사진을 떠올려 보세요. 옆 픽셀과 색이 거의 같죠? PNG는 각 픽셀의 절대 색상값 대신, 바로 옆 픽셀과의 차이를 저장합니다. 비슷한 색이 연속되면 차이값이 0에 가까워져서 데이터가 훨씬 단순해집니다.

예시: 파란 하늘 픽셀 5개

원본:
120 122 121 123 122
필터 후:
120 +2 -1 +2 -1
← 작은 숫자들!
2 Deflate 압축 — 반복 제거 + 짧은 코드 배정

LZ77 — 반복 패턴 찾기

이미 나온 패턴이 다시 나오면, 데이터를 반복해서 쓰는 대신 "앞에서 N번째, L개 복사"라고만 기록합니다.

원본: ABCABCABC

→ ABCABC(6칸 전, 3개 복사)

허프만 코딩 — 빈도별 코드 배정

자주 나타나는 값에는 짧은 코드를, 드물게 나타나는 값에는 긴 코드를 배정합니다.

자주 등장: 0 → "1" (1비트)

가끔 등장: +2 → "01" (2비트)

드물게: 120 → "001" (3비트)

핵심 정리: PNG는 ①이웃 픽셀과의 차이를 기록해 숫자를 작게 만들고 → ②반복 패턴을 참조로 대체하고 → ③자주 나오는 값에 짧은 코드를 배정합니다. 이 과정에서 어떤 정보도 버리지 않으므로 원본과 100% 동일하게 복원됩니다.

GIF 압축 원리

색상 테이블 + LZW 알고리즘

GIF는 먼저 색상 수를 줄이고, 그 다음 반복 패턴을 제거합니다.

1 색상 테이블 — 최대 256색으로 줄이기

원본 이미지에서 가장 많이 사용된 최대 256가지 색을 골라 "색상표(팔레트)"를 만듭니다. 그리고 각 픽셀에는 색상 자체(24비트) 대신 색상표의 번호(8비트)만 기록합니다.

색상 테이블 예시

0
1
2
3
… 최대 256개

원본 픽셀: 24비트 × 색 정보 → 용량 큼

GIF 픽셀: 8비트 × 번호만 → 용량 1/3로 감소!

2 LZW 압축 — 반복되는 픽셀 패턴을 사전에 등록

LZW(Lempel-Ziv-Welch) 알고리즘은 픽셀을 읽으면서 이전에 나온 패턴이 다시 나타나면 사전의 짧은 코드 하나로 대체합니다. 같은 색이 반복될수록 압축 효과가 커집니다.

동작 예시

픽셀 데이터: 0 1 0 1 0 1 0 1 …

처음 보는 패턴 "0,1"을 사전에 등록 → 코드 256

"0,1" 재등장 시 → 코드 256 하나로 대체

→ 반복이 많을수록 사전이 커지고, 압축률이 높아짐!

핵심 정리: GIF는 ①색상을 최대 256개로 줄여 픽셀당 용량을 1/3로 낮추고 → ②LZW 알고리즘으로 반복 패턴을 짧은 코드로 대체합니다. 원본이 256색 이하이면 비손실이지만, 256색을 초과하면 색 정보가 손실됩니다.

JPEG 압축 원리

손실 압축 — 색상 변환 + DCT + 양자화 + 허프만

JPEG는 "사람의 눈이 잘 느끼지 못하는 정보를 과감히 버린다"는 아이디어에 기반합니다. 총 4단계를 거치며, 각 단계마다 데이터가 점점 줄어듭니다.

1 색상 공간 변환 — RGB → YCbCr

RGB(빨강·초록·파랑)를 밝기(Y)와 색차(Cb, Cr)로 분리합니다. 사람의 눈은 밝기 변화에는 민감하지만, 색 변화에는 둔감합니다. 그래서 색차 정보를 절반으로 줄여도(크로마 서브샘플링) 거의 차이를 느끼지 못합니다.

Y (밝기)

해상도 유지

Cb (색차)

절반으로 축소

Cr (색차)

절반으로 축소

2 DCT 변환 — 이미지를 주파수로 분해

이미지를 8×8 픽셀 블록으로 나눈 뒤, 각 블록을 DCT(이산 코사인 변환)를 적용하여 "주파수" 정보로 바꿉니다. 천천히 변하는 부분(저주파)은 큰 값으로, 빠르게 변하는 세밀한 부분(고주파)은 작은 값으로 나타납니다.

3 양자화 — 세밀한 정보 버리기 (여기서 손실 발생!)

고주파 성분(세밀한 디테일)의 값을 큰 수로 나누어 0에 가깝게 만듭니다. 사람의 눈이 잘 인식하지 못하는 미세한 차이를 과감히 제거하는 것입니다. 이 단계에서 품질 설정에 따라 얼마나 많이 버릴지 결정됩니다.

양자화 전후 비교 (8×8 블록 일부)

DCT 후:

412 -28 -61  18
-36   7  23 -12
-15   9  -6   3
  4  -2   1   1

양자화 후:

26  -2  -4   1
-2   0   1   0
-1   0   0   0
 0   0   0   0

많은 값이 0이 되어 데이터가 크게 줄어듭니다!

4 엔트로피 코딩 — 남은 데이터 압축

양자화로 0이 많아진 데이터를 런-렝스 인코딩(연속된 0의 개수 기록)과 허프만 코딩(자주 나오는 값에 짧은 코드)으로 최종 압축합니다. 이 단계는 비손실이며, PNG와 유사한 원리입니다.

핵심 정리: JPEG는 ①색차 정보를 줄이고 → ②이미지를 주파수로 변환하고 → ③눈에 안 보이는 고주파를 제거하고 → ④남은 데이터를 허프만 코딩으로 압축합니다. 세밀한 정보를 버리기 때문에 원본 복원은 불가능하지만, 파일 크기를 극적으로 줄일 수 있습니다.

파일 크기 비교

File Size Comparison

같은 이미지를 다른 파일 형식으로 저장했을 때의 크기를 비교해 봅시다. 압축 방식에 따라 파일 크기가 크게 달라집니다.

BMP
236 KB
PNG
142 KB
GIF
59 KB
JPEG
8 KB

정리

BMP(236KB) > PNG(142KB) > GIF(59KB) > JPEG(8KB) 순으로 파일 크기가 작아집니다. JPEG는 손실 압축을 사용하여 가장 높은 압축률을 보여주지만, 이미지 품질 손실이 발생합니다. PNG는 비손실 압축으로 품질을 유지하면서도 BMP보다 훨씬 작은 크기를 가집니다.

핵심 정리

Key Summary

BMP 파일

  • 각 화소에 색 정보를 차례대로 기록
  • 무압축 파일 형식 (확장자 .bmp)
  • 이미지 품질 우수, 파일 크기 큼

이미지 압축

  • PNG: 비손실 압축, 트루 컬러, 고품질
  • GIF: 256색 제한, 파일 크기 작음, 애니메이션 지원
  • JPEG: 손실 압축, 높은 압축률, 사진에 적합
