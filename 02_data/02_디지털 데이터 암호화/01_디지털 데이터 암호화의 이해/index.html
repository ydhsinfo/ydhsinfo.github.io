디지털 데이터 암호화란?

Digital Data Encryption

핵심 개념

디지털 데이터 암호화란 권한이 없는 사람이 데이터를 알아볼 수 없게 변환하는 기술입니다. 인터넷 뱅킹, 메신저, 이메일 등 우리가 일상에서 사용하는 거의 모든 디지털 서비스에서 암호화 기술이 활용되고 있습니다.

암호화 (Encryption)

평문 → 암호문

평문(plaintext)을 암호문(ciphertext)으로 바꾸는 과정입니다.

LOVE 키=3 ORYH

복호화 (Decryption)

암호문 → 평문

암호문(ciphertext)을 다시 평문(plaintext)으로 복원하는 과정입니다.

ORYH 키=3 LOVE

암호화의 구성 요소

키 (Key)

암호 알고리즘 내에서 평문을 암호문으로 변경할 때 사용하는 문자열입니다. 올바른 복호화 키를 가진 사람만이 암호문을 해독할 수 있으므로, 키 관리가 매우 중요합니다.

암호 알고리즘

데이터를 암호화하고 복호화하는 수학적 절차입니다. 카이사르 암호, AES, RSA 등 다양한 알고리즘이 있으며, 알고리즘의 강도에 따라 보안 수준이 달라집니다.

키 관리의 중요성

아무리 강력한 암호 알고리즘을 사용하더라도, 키가 유출되면 암호문이 쉽게 해독될 수 있습니다. 따라서 키를 안전하게 생성, 저장, 전달, 폐기하는 것이 암호화에서 가장 중요한 과제입니다.

암호화 / 복호화 흐름

Encryption & Decryption Flow

평문이 키와 암호 알고리즘을 통해 암호문으로 변환되고, 올바른 키로 다시 평문으로 복원됩니다.

카이사르 암호 알고리즘

카이사르 암호란?

고대 로마의 줄리어스 카이사르(Julius Caesar)가 사용한 가장 기본적인 암호 방식입니다. 알파벳을 키(key) 값만큼 이동하여 다른 알파벳으로 치환하는 방식으로 동작합니다.

Chapter Summary

암호화의 개념

  • 권한 없는 사람이 데이터를 알아볼 수 없게 변환하는 기술
  • 암호화(평문 → 암호문)와 복호화(암호문 → 평문)
  • 구성 요소: 키(key)와 암호 알고리즘

암호화 방식 비교

  • 대칭키: 같은 키로 암호화/복호화 (빠르지만 키 전달 위험)
  • 공개키: 다른 키로 암호화/복호화 (안전하지만 느림)
  • 카이사르 암호: 알파벳 이동 방식의 대칭키 암호

대칭키 암호화 (Symmetric Encryption)

하나의 키로 암호화와 복호화를 모두 수행

원리

대칭키 암호화는 암호화와 복호화에 같은 키를 사용합니다. 자물쇠 하나에 열쇠 하나가 있는 것과 같습니다. 보내는 사람과 받는 사람이 동일한 비밀 키를 공유해야 합니다.

평문

Hello

같은 키

암호문

Xk#9p

같은 키

복호화

Hello

장점
  • 처리 속도가 매우 빠름 — 단순한 비트 연산(XOR, 치환, 자리이동)으로 구성
  • 대용량 데이터 암호화에 적합
단점
  • 키 전달 문제 — 상대방에게 키를 안전하게 전달하기 어려움
  • 통신 상대가 많아지면 관리해야 할 키 수가 급증
필요한 키의 개수

N명이 서로 비밀 통신을 하려면, 모든 1:1 조합마다 키가 하나씩 필요합니다.

키 개수 = N × (N - 1) / 2

공개키 암호화 (Asymmetric Encryption)

공개키로 암호화, 개인키로 복호화

공개키 암호화는 두 개의 키를 사용합니다. 누구나 볼 수 있는 공개키(Public Key)로 암호화하고, 본인만 가진 개인키(Private Key)로 복호화합니다.

왜 안전한가?

공개키 암호화의 안전성은 "수학적으로 한 방향은 쉽지만, 반대 방향은 극도로 어려운 문제"에 기반합니다.

비유: 색깔 섞기

노란색 + 파란색 = 초록색 만들기는 쉽습니다. 하지만 초록색을 보고 "정확히 어떤 노란색과 어떤 파란색을 섞었는지" 알아내는 것은 매우 어렵습니다. 공개키 암호화도 마찬가지입니다. 큰 수의 곱셈은 쉽지만, 소인수분해는 극도로 어렵습니다.

예시: 61 × 53 = 3,233 계산은 1초면 됩니다.
하지만 3,233 = ? × ?를 풀려면 하나씩 나눠봐야 합니다.
실제 RSA에서는 수백 자리의 숫자를 사용하므로, 현존하는 모든 컴퓨터로도 풀 수 없습니다.

장점
  • 키 전달 문제 해결 — 공개키는 누구에게나 공개해도 안전
  • 키 관리가 간편 (N명이면 2N개의 키만 필요)
단점
  • 처리 속도가 느림 — 큰 수의 거듭제곱, 나머지 연산 필요
  • 대용량 데이터에는 단독 사용 비효율적
필요한 키의 개수

각 사람이 공개키 1개 + 개인키 1개만 가지면 됩니다. 상대가 누구든 상관없습니다.

키 개수 = 2N

처리 속도는 왜 차이가 날까?

대칭키 암호화는 공개키 암호화보다 약 100~1,000배 빠릅니다. 왜일까요?

대칭키 (빠름)

내부적으로 비트 XOR, 자리 바꾸기, 표 치환 등 컴퓨터가 가장 빠르게 처리하는 단순 연산을 사용합니다.

XOR: 0110 ⊕ 1010 = 1100

→ CPU가 1클럭에 처리!

공개키 (느림)

수백 자리 큰 수의 거듭제곱과 나머지 연산(mod)을 반복합니다. 연산량이 비교할 수 없이 많습니다.

Me mod N (수백 자리!)

→ 수천~수만 클럭 필요

실제 인터넷(HTTPS)에서는? 처음 연결할 때 공개키로 안전하게 대칭키를 전달하고, 이후 실제 데이터는 대칭키로 빠르게 암호화합니다. 두 방식의 장점을 결합한 것이 하이브리드 암호화입니다.

AES 암호화 원리

Advanced Encryption Standard — 현재 가장 널리 쓰이는 대칭키 암호

AES는 데이터를 128비트(16바이트) 블록으로 나누고, 각 블록에 대해 여러 라운드의 변환을 반복 적용합니다. AES-128은 10라운드, AES-256은 14라운드를 수행합니다.

1 SubBytes — 바이트 치환

각 바이트를 S-Box(치환 표)를 이용하여 다른 값으로 바꿉니다. 예를 들어 0x53은 0xED로 치환됩니다. 원본과 완전히 다른 값으로 바뀌므로 패턴을 숨길 수 있습니다.

2 ShiftRows — 행 이동

데이터를 4×4 격자에 배치한 후, 각 행을 왼쪽으로 밀어냅니다. 1행은 0칸, 2행은 1칸, 3행은 2칸, 4행은 3칸 이동합니다.

이동 전

ABCD EFGH IJKL MNOP

이동 후

ABCD FGHE KLIJ PMNO
3 MixColumns — 열 섞기

각 열의 4개 바이트를 수학적 연산으로 섞습니다. 한 바이트가 바뀌면 같은 열의 다른 바이트도 모두 영향을 받아, 데이터가 더 복잡하게 뒤섞입니다.

4 AddRoundKey — 라운드 키 XOR

원래 키에서 파생된 라운드 키와 데이터를 XOR 연산합니다. 이 과정을 통해 키를 모르면 절대 복호화할 수 없게 됩니다.

이 4단계를 10~14번 반복하면 원본 데이터가 완전히 알아볼 수 없는 암호문이 됩니다.

RSA 암호화 원리

가장 대표적인 공개키 암호 — 소인수분해의 어려움에 기반

RSA는 두 개의 큰 소수를 이용하여 키 쌍을 만듭니다. 원리를 작은 수로 단계별로 알아봅시다.

키 생성 과정

1 소수 두 개를 선택

p = 61, q = 53

2 N = p × q 계산

N = 61 × 53 = 3,233

3 φ(N) = (p-1) × (q-1) 계산

φ(N) = 60 × 52 = 3,120

4 공개 지수 e 선택 (φ(N)과 서로소)

e = 17

5 비밀 지수 d 계산 (e × d mod φ(N) = 1)

d = 2,753  (17 × 2,753 = 46,801 = 15 × 3,120 + 1)

공개키 (누구나 볼 수 있음)

(e, N) = (17, 3233)

개인키 (본인만 보관)

(d, N) = (2753, 3233)

암호화와 복호화

암호화

C = Me mod N

예: M = 65 (문자 'A')
C = 6517 mod 3233 = 2,790

복호화

M = Cd mod N

C = 2,790
M = 27902753 mod 3233 = 65 (= 'A')
