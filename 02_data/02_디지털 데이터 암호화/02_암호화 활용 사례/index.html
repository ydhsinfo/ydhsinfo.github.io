고대 · 근대 암호화

적군으로부터 아군의 정보를 보호하기 위한 목적

전치 암호

평문의 문자를 자리 바꿔 암호화하는 방식입니다. 원래 문자는 그대로 사용하되, 순서를 재배열하여 의미를 숨깁니다.

핵심: 문자는 동일, 위치만 변경

치환 암호

평문의 문자를 다른 문자로 대체하여 암호화하는 방식입니다. 원래 문자를 규칙에 따라 전혀 다른 문자로 바꿉니다.

핵심: 위치는 동일, 문자를 대체

작동 원리

  1. 1 굵기와 길이가 같은 나무 막대기를 송신자와 수신자가 공유합니다.
  2. 2 양피지 리본을 막대기에 감은 뒤 옆으로 메시지를 작성합니다.
  3. 3 리본을 풀면 문자의 순서가 뒤섞여 원래 메시지를 알 수 없게 됩니다.
  4. 4 수신자가 같은 막대기에 감으면 원문을 복원할 수 있습니다.

암호화 예시

평문 Secret Message
암호문 (전치) Stse acMgreees

작동 원리

평문의 각 문자를 키(key)만큼 평행 이동한 문자로 치환합니다. 예를 들어, key=3이면 A는 D로, B는 E로, S는 V로 바뀝니다.

카이사르는 실제로 key=3을 사용하여 군사 기밀 통신에 활용했다고 전해집니다.

카이사르 암호 체험하기

암호문 결과:
VHFUHW

에니그마, 쉽게 이해하기

에니그마는 제2차 세계대전 때 독일군이 사용한 기계식 암호 장치입니다. 겉보기에는 타자기처럼 생겼지만, 내부에는 복잡한 전기 회로가 숨겨져 있습니다.

글자를 입력하면 배전반(플러그보드)에서 먼저 1차로 글자가 바뀌고, 이어서 회전자(로터)를 거치면서 2차, 3차로 계속 바뀝니다. 마치 자물쇠 비밀번호를 여러 번 돌리는 것처럼, 여러 단계를 거칠수록 해독이 어려워집니다.

1단계: 키보드

암호화할 글자를
키보드로 누릅니다

H
2단계: 배전반

케이블 연결에 따라
글자가 1차 치환됩니다

H M
3단계: 회전자

회전자를 통과하며
2차, 3차 치환됩니다

M T
핵심: 회전자는 글자를 하나 입력할 때마다 한 칸씩 회전합니다. 그래서 같은 글자 'L'을 두 번 입력해도 매번 다른 글자로 변환됩니다! 이것이 에니그마를 단순한 치환 암호와 구별 짓는 핵심 원리입니다.

현대 암호화

디지털 시대의 정보 보호 기술

해시 함수란?

  • 별도의 키 없이 일정 규칙을 적용하여 고정된 길이의 해시값을 출력
  • 암호화만 가능하고, 복원(복호화)은 불가능 (일방향 함수)
  • 패스워드가 유출되어도 원본 비밀번호를 복원할 수 없음
  • 로그인 시 입력값을 해시화하여 저장된 해시값과 비교

보안 핵심 포인트

해시 함수는 암호화만 가능하고 복원이 불가능하기 때문에, 패스워드가 유출되어도 원래 비밀번호를 알아낼 수 없습니다. 로그인 시에는 입력한 비밀번호를 다시 해시화하여 저장된 해시값과 비교합니다.

디지털 서명, 쉽게 이해하기

우리가 계약서에 서명하면 "이 계약서는 내가 쓴 것"이라는 증거가 됩니다. 디지털 서명도 마찬가지로, "이 메시지는 정말 내가 보낸 것"을 증명하는 기술입니다.

실생활의 서명/도장은
누구나 모양을 볼 수 있지만
만들 수 있는 건 본인뿐

공개키로 누구나 검증 가능
하지만 서명을 만들 수 있는 건
개인키 소유자뿐

송신자: 서명 만들기

STEP 1
원본 메시지 준비

보내고 싶은 메시지를 준비합니다.

"100만원을 입금합니다"
STEP 2
해시값 생성

해시 함수로 메시지를 짧은 고정 길이 값으로 변환합니다. (메시지의 '지문' 같은 역할)

해시값: a3f2b8c1
STEP 3
개인키로 해시값 암호화 = 디지털 서명!

나만 가지고 있는 개인키(Private Key)로 해시값을 암호화합니다.

a3f2b8c1 + 개인키 = x9k2m4p7

이 암호화된 값이 바로 "디지털 서명"입니다

원본 메시지 + 디지털 서명을 함께 전송

수신자: 서명 검증하기

STEP 1
공개키로 디지털 서명 복호화

송신자의 공개키(Public Key)로 디지털 서명을 복호화하여 해시값을 꺼냅니다.

x9k2m4p7 + 공개키 = a3f2b8c1
STEP 2
수신 메시지에도 같은 해시 함수 적용

받은 메시지에 같은 해시 함수를 적용하여 해시값을 직접 계산합니다.

해시값: a3f2b8c1
STEP 3
두 해시값 비교

두 해시값이 일치하면 ➜ 이 메시지는 정말 송신자가 보낸 것이고, 중간에 변조되지 않았음!

복호화한 해시값
a3f2b8c1
=
직접 계산한 해시값
a3f2b8c1
신원 확인 + 위변조 방지 완료!
인증 (Authentication)

개인키는 송신자만 가지고 있으므로, 서명이 유효하면 진짜 그 사람이 보낸 것이 증명됩니다.

무결성 (Integrity)

메시지가 조금이라도 바뀌면 해시값이 달라지므로, 중간에 변조되지 않았음이 보장됩니다.

HTTPS, 쉽게 이해하기

인터넷 쇼핑을 할 때 카드 번호를 입력하면, 그 정보가 인터넷을 통해 서버로 전달됩니다. 만약 이 정보가 암호화 없이 전송된다면? 누군가 중간에서 엿볼 수 있겠죠!

HTTP (암호화 X)

"카드번호: 1234-5678"이
그대로 전송

HTTPS (암호화 O)

"x7#kQ!9m2$pL"처럼
암호화되어 전송

HTTPS 연결 과정 (TLS 핸드셰이크)

HTTPS의 핵심 아이디어: 공개키 암호화는 안전하지만 느리고, 대칭키 암호화는 빠르지만 키를 안전하게 전달하기 어렵습니다. 그래서 HTTPS는 처음에만 공개키 암호화로 대칭키를 안전하게 전달하고, 그 후에는 대칭키 암호화로 빠르게 데이터를 전송합니다. 두 방식의 장점만 조합한 것이죠!

자물쇠를 클릭하면? - SSL 인증서 확인

브라우저 주소창의 자물쇠 아이콘을 클릭하면 해당 웹사이트의 SSL 인증서 정보를 확인할 수 있습니다.

https:// www.bank.com

자물쇠를 클릭해보세요!

연결이 안전합니다
인증서 (유효)

이 사이트는 유효한 인증서를 가지고 있으며,
신뢰할 수 있는 기관에서 발급했습니다.

발급 대상 www.bank.com
발급 기관 (CA) DigiCert Inc
유효 기간 2025.01.01 ~ 2026.12.31
암호화 방식 RSA 2048-bit
지문 (SHA-256) A3:F2:B8:C1:...
SSL 인증서란?

웹사이트의 신분증과 같습니다. 신뢰할 수 있는 인증기관(CA)이 발급하며, "이 웹사이트는 진짜입니다"를 보증합니다.

인증기관(CA)이란?

주민등록증을 정부가 발급하듯, SSL 인증서는 인증기관이 발급합니다. DigiCert, Let's Encrypt 등이 대표적인 인증기관입니다.

주의! 이런 경고가 뜨면?

"이 연결은 비공개가 아닙니다" 경고가 뜨면 인증서가 만료되었거나 위조 사이트일 수 있습니다. 개인정보를 절대 입력하지 마세요!

HTTPS에서 사용되는 암호화 방식 비교

구분 공개키 암호화 대칭키 암호화
용도 인증서 검증 + 대칭키 전달 실제 데이터 전송
키 공개키 + 개인키 (2개) 동일한 키 1개 공유
사용 시점 처음 연결할 때만 (핸드셰이크) 핸드셰이크 이후 데이터 전송
특징 보안성 높음, 속도 느림 속도 빠름, 대량 데이터에 적합

학습 내용 정리

고대 · 근대 암호화

  • 전치 암호 - 문자의 위치를 재배열 (스키테일)
  • 치환 암호 - 문자를 다른 문자로 대체 (카이사르)
  • 에니그마 - 기계식 다중 치환 (배전반 + 회전자)

현대 암호화

  • 패스워드 - 해시 함수로 일방향 암호화
  • 디지털 서명 - 개인키로 서명, 공개키로 검증
  • HTTPS - 공개키(인증) + 대칭키(전송) 조합
